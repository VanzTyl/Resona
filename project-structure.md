# <span style="color: rgb(37, 99, 235);">Project Structure</span>

A standardized project layout for organizing the frontend, backend, and database components.

---

## <span style="color: rgb(22, 163, 74);">Root Directory</span>

```text
project/
├── frontend/
├── backend/
└── database/
```

---

## <span style="color: rgb(245, 158, 11);">Frontend Structure</span>

```text
frontend/
├── .env.example
└── src/
    ├── pages/
    │   ├── {page_name}/
    │   │   ├── {page_name}.html
    │   │   ├── {page_name}.js
    │   │   ├── {page_name}-helpers.js      (optional)
    │   │   └── styles/
    │   │       └── {page_name}.css
    │   │
    │   └── ... (other pages)
    │
    ├── globals/
    │   └── components/
    │       ├── api-client.js
    │       ├── icons.js
    │       ├── theme.js
    │       ├── button.js
    │       ├── modal.js
    │       ├── toast.js
    │       ├── skeleton-loader.js
    │       └── feed-card.js
    │
    ├── index.html
    ├── style.css
    ├── script.js
    ├── sidebar.js
    └── env-config.js
```

### Directory Purpose

| Directory/File | Description |
| --- | --- |
| `pages/` | Contains all application pages. |
| `pages/{page_name}/{page_name}.html` | Static HTML template for the page (SPA partial). |
| `pages/{page_name}/{page_name}.js` | Page controller: rendering, data loading, event handling. |
| `pages/{page_name}/{page_name}-helpers.js` | Optional helper functions extracted from page controller. |
| `pages/{page_name}/styles/{page_name}.css` | Page-specific stylesheets. |
| `globals/` | Shared resources used across all pages. |
| `globals/components/` | Reusable JS components (api-client, icons, theme, toast, modal, etc.). |
| `index.html` | Application entry page (SPA shell). |
| `style.css` | Global stylesheet (design tokens, reset, layout, shared components). |
| `script.js` | Global JavaScript entry point (router, nav, sidebar, init). |
| `env-config.js` | Runtime environment configuration (generated by build). |

## <span style="color: rgb(139, 92, 246);">Backend Structure</span>

```text
backend/
├── .env.example
└── src/
    ├── controllers/
    │   ├── auth-controller.php
    │   ├── user-controller.php
    │   ├── friend-controller.php
    │   ├── feed-controller.php
    │   ├── message-controller.php
    │   ├── reaction-controller.php
    │   ├── sync-controller.php
    │   ├── dashboard-controller.php
    │   ├── discover-controller.php
    │   ├── onboarding-controller.php
    │   └── token-helper.php
    │
    ├── index.php
    ├── router.php
    ├── config.php
    ├── constants.php
    ├── middleware.php
    ├── database.php
    ├── schema.md
    └── version.md
```

### Directory Purpose

| Directory/File | Description |
| --- | --- |
| `controllers/` | Request handling and business logic (one file per domain). |
| `index.php` | Application entry point (bootstrap, routing dispatch, CORS). |
| `router.php` | Route definitions mapping HTTP methods/paths to controller functions. |
| `config.php` | Environment variable loading and config accessors. |
| `constants.php` | Application-wide constants (validation, limits, encryption). |
| `middleware.php` | Auth middleware (JWT extraction and validation). |
| `database.php` | Database connection (PDO with TiDB-compatible settings). |
| `schema.md` | Backend architecture documentation. |
| `version.md` | Backend version history. |

## <span style="color: rgb(220, 38, 38);">Database Structure</span>

```text
database/
├── .env.example
└── src/
    ├── migrations/
    │   ├── up_001.sql
    │   ├── down_001.sql
    │   ├── up_002.sql
    │   ├── down_002.sql
    │   ├── up_003.sql
    │   └── down_003.sql
    │
    ├── init.sql
    ├── schema.md
    └── version.md
```

### Directory Purpose

| Directory/File | Description |
| --- | --- |
| `migrations/` | Database migration scripts. |
| `up_{version}.sql` | Applies a database migration. |
| `down_{version}.sql` | Reverts a database migration. |
| `init.sql` | Executes all available `up_*.sql` migrations in order. |
| `schema.md` | Database schema documentation. |
| `version.md` | Database version history. |

---

## <span style="color: rgb(15, 118, 110);">Structure Summary</span>

| Component | Main Directories | Documentation |
| --- | --- | --- |
| Frontend | `pages/`, `globals/components/` | `index.html`, `style.css`, `script.js` |
| Backend | `controllers/` | `index.php`, `router.php`, `config.php` |
| Database | `migrations/` | `init.sql`, `version.md` |

---

## <span style="color: rgb(37, 99, 235);">Notes</span>

- Every major component maintains its own `schema.md` for documentation.
- Each component tracks its own release history using `version.md`.
- Database schema changes should always be made through migration files.
- Shared frontend assets belong in `globals`, while page-specific resources belong inside their respective page directories.
- Each base component (`frontend`, `backend`, and `database`) must include a `.env.example` file documenting all required environment variables.
- Actual `.env` files are environment-specific and must never be committed to version control.
- Whenever a new environment variable is introduced, the corresponding `.env.example` file must be updated in the same commit.
